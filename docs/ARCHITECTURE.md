# Architecture

The Streamlit entry point loads a ZIP into memory. The bundle loader checks archive limits, provenance metadata, image sizes, array types, and numerical values. A browser session retains the current validated bundle for widget interactions. The viewer reads those arrays in their stored vertex frame. Plotly manages the interactive viewport. An optional Open3D module computes normals, bounds, and topology statistics and serializes meshes independently of the viewport.

The Colab runner detects people with TorchVision, passes their boxes to the official `ViTDetDataset` crop implementation, and runs the official `load_hmr2` checkpoint. HMR2 provides `pred_smpl_params` with beta coefficients and rotation matrices, `pred_vertices` before camera translation, and topology from `model.smpl.faces`. The runner uses the official crop-to-full camera conversion and renderer for the overlay and per-person side views. The exporter writes CPU NumPy arrays and validates the finished ZIP with the Windows viewer's loader. [Official demo](https://github.com/shubham-goel/4D-Humans/blob/main/demo.py) · [HMR2 forward](https://github.com/shubham-goel/4D-Humans/blob/main/hmr2/models/hmr2.py) · [Checkpoint loader](https://github.com/shubham-goel/4D-Humans/blob/main/hmr2/models/__init__.py)

The optional SMPL Explorer loads the authorized neutral asset into `smplx.SMPLLayer` on CPU and verifies the reference before enabling editing. The Streamlit session keeps per-person edit copies of β and the joint rotations. SMPL Forward creates canonical and posed vertices for Plotly while the imported prediction stays available for comparison. [SMPL-X implementation](https://github.com/vchoutas/smplx)

The scene/frame/camera tuple identifies the source observation. Person IDs are scoped to that observation. A later association layer can group observations under an actor ID while retaining individual predictions and provenance. OmniRe projects annotated 3D boxes, runs per-camera PHALP tracks with 4D-Humans predictions, and matches tracks using image-box IoU across frames before temporal postprocessing. Phase 1 consumes one prepackaged camera observation. Phase 4 will use single-frame projected-cuboid matching and select the largest usable matched view while keeping the alternatives. [OmniRe human pose processing](https://github.com/ziyc/drivestudio/blob/main/docs/HumanPose.md) · [OmniRe postprocessing](https://github.com/ziyc/drivestudio/blob/main/datasets/tools/postprocess.py) · [OmniRe PandaSet preparation](https://github.com/ziyc/drivestudio/blob/main/docs/Pandaset.md) · [PandaSet devkit](https://github.com/scaleapi/pandaset-devkit)

See [Open3D TriangleMesh](https://www.open3d.org/docs/release/python_api/open3d.geometry.TriangleMesh.html) for topology checks and geometry methods.
